# PolarGrid AI

A full-stack energy management platform concept for an Antarctic research
station: live telemetry, AI-driven forecasting, battery and load management,
an emergency center, and a digital twin of the station.

```
polargrid-ai/
├── backend/     Node.js + Express API (mock telemetry engine)
└── frontend/    React + Vite single-page app
```

## Quick start

Open two terminals.

**1. Backend**

```bash
cd backend
npm install
npm start
```

Runs on `http://localhost:4000`. Health check: `GET /api/health`.

**2. Frontend**

```bash
cd frontend
npm install
npm run dev
```

Runs on `http://localhost:5173` and proxies `/api/*` to the backend
(configured in `vite.config.js`).

Open `http://localhost:5173/login`.

Accounts are **invite-only** — there is no public signup form. On first
run, the backend seeds one admin account so someone can start inviting
people:

| Role | Email | Password |
| --- | --- | --- |
| Admin | admin@polarstation.org | polar2026 |

**Change that password immediately** (there's no "change password" UI yet —
update it directly in the `users` table, or delete `backend/data/polargrid.db`
and re-seed with a different value in `backend/db.js`).

### Inviting new users

1. Sign in as the admin and open **Invites** in the sidebar (admin-only).
2. Enter the new person's email and role, click **Generate invite**. You'll
   get a one-time link like `http://localhost:5173/signup/<code>`.
3. Send that link to them. It's valid for 7 days and can only be used once,
   only for the email/role it was issued for.
4. They open the link, set a name and password (8+ chars), and are signed
   in immediately.

There's no way to create an account without a valid invite code — the
`/api/auth/signup` endpoint checks the code against the `invites` table and
rejects anything expired, already-used, or unknown.

## What's implemented

**Backend (`/backend`)**
- `POST /api/auth/login`, `/logout`, `GET /api/auth/me` — token-based auth
  backed by a real SQLite database (`backend/data/polargrid.db`), with
  bcrypt-hashed passwords
- `POST /api/auth/invites` (admin only), `GET /api/auth/invites` (admin
  only, list), `GET /api/auth/invites/:code` (public, validate),
  `POST /api/auth/signup` (public, requires a valid invite code) — the
  invite-only account creation flow
- `GET /api/dashboard` — station snapshot, AI status, 24h series
- `GET /api/energy?range=1h|6h|24h|7d|30d` — generation/consumption breakdown + series
- `GET /api/predictions` — 6h forecast, risk level, AI recommendation
- `GET /api/battery` — charge, health, temperature-adjusted capacity, recommendation
- `GET /api/renewable` — solar/wind detail + 24h forecast
- `GET /api/loads`, `POST /api/loads/:id/toggle` — load list with cycling status
- `GET /api/emergency` — safety status + alerts
- `GET /api/twin` — station zones for the digital twin
- `GET /api/reports?period=daily|weekly|monthly|yearly` — performance metrics
- `GET/PUT /api/settings` — station configuration

All telemetry is generated by `backend/data/simulate.js`. Swap that module
out for real sensor/database reads to go from demo to production — the
route contracts stay the same.

**Frontend (`/frontend`)**
- All 11 pages from the site map: Login, Dashboard, Energy Monitoring, AI
  Predictions, Battery Management, Renewable Energy, Load Management,
  Emergency Center, Digital Twin, Reports & Analytics, Settings
- Shared sidebar/topbar layout, polar-station visual system (dark navy,
  ice/aurora accents, mono telemetry readouts)
- Dashboard and Emergency Center poll the backend for a "live" feel
- Load Management and Settings write back to the backend (toggle loads,
  persist thresholds)

## Notes on hardening this for real use

This is a working demo scaffold, not a production system. Before deploying:
- Swap SQLite for a managed database (Postgres, etc.) if you need
  concurrent writers or multi-instance deployment
- Move session tokens to signed, expiring JWTs instead of opaque tokens
  stored in a `sessions` table
- Send invite links by email automatically (right now an admin has to copy
  and paste the link manually) and rate-limit invite creation
- Replace `backend/data/simulate.js` with real sensor ingestion
- Add HTTPS, environment-based config, and rate limiting
- Add input validation on all `PUT`/`POST` routes
- Add a "change password" / "reset password" flow
